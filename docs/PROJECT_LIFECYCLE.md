# 项目管理修复记录

2026-11-17：补齐项目删除、回收站恢复和重命名的真实业务流程。

## 用户行为

- 删除项目时先确认，项目移入应用回收站。项目数据库、原始素材、生成历史和导出文件全部保留，不执行磁盘删除。
- 回收站可恢复完整项目；删除前已经打开的播放链接在项目处于回收站时失效。
- 生成、导出或素材导入尚未结束时不允许删除，返回明确提示，不替用户取消云端任务或重复生成。
- 重命名支持简体中文，去除首尾空格并拒绝空名称；同时更新最近项目列表，支持撤销/重做。
- 导入 TXT/SRT/VTT 的新台词继承已配置的连接、模型和音色；已有台词不被改写。

## 接口

所有接口继续使用本地会话认证：

- `DELETE /api/v1/projects/{id}`，JSON `{revision}`，返回 `{id,name,deleted_at}`。
- `GET /api/v1/projects/trash`，返回 `{id,name,created_at,updated_at,deleted_at}` 数组。
- `POST /api/v1/projects/{id}/restore-trash`，返回完整项目。
- 改名继续使用 `PATCH /api/v1/projects/{id}`，JSON `{revision,name}`。

已删除项目普通访问返回 `410 PROJECT_TRASHED`。任务忙返回 `409 PROJECT_BUSY`，版本过期返回 `409 REVISION_CONFLICT`。

## 数据与并发

应用数据库升级到版本 3，迁移前写入 `studio.pre-migration.sqlite`，新增独立 `project_trash` 表。项目数据库保持版本 2，因此已有项目备份格式不变。

删除与生成入队/状态发布共享项目锁。长时间导入/重新连接素材使用操作计数，在异步处理期间禁止删除但不持有阻塞锁。每次访问项目时检查回收站状态，包括已缓存数据库引擎的路径。

## 验证

`backend/tests/test_project_lifecycle.py` 验证素材内容不变、删除后媒体失效、恢复后数据完整、重命名与撤销、旧版本拒删、忙状态保护、异步导入竞态、重启持久化、迁移备份以及导入台词默认连接。

测试使用本地测试素材，不调用付费云端接口，不对用户真实项目执行删除操作。
